# Fan-out subagent guards — /self-improve

Guards for the parallel-analysis fan-out (full reviews without a same-day
pass). Read before spawning subagents; each guard exists because its failure
mode occurred in a live run.

- **One shared brief block**: compose the session context + suppression list ONCE and paste it verbatim into every subagent prompt — per-agent prompt drift converts known-fixed issues back into phantom findings the main session then has to re-refute. End every spawn prompt with an explicit instruction to send findings back to the main session when done — weaker phrasings produce agents that finish silently. This applies regardless of the agent type's declared tool list: messaging back is harness-provided, and "its tools don't include messaging" is exactly the rationalization that reproduces a silent idle.
- **Memory-agent briefs must state the link convention**: if memory files cross-reference with `[[name]]` wiki-links, links resolve by the target file's frontmatter `name:` slug (verify with `grep '^name:'`), not the filename stem. Verify broken-link findings against BOTH resolutions before presenting — mixed conventions exist in older memory directories.
- **Idle-without-report agents**: idle ≠ "no issues". If a subagent goes idle without posting findings, message it for the final list (or "No issues found") and wait before compiling.
- **Discard session-state findings**: if a subagent reports the current session's model, effort, or permissions, discard it — subagents run their own configuration and cannot observe the parent session.
- **Spot-verify file-content claims before presenting**: grep the cited file for the quoted defect — subagents misattribute text across files and may have read pre-edit state (findings on files this session edited deserve extra suspicion). Use fixed-string matching (`grep -F`); quotes with backticks, em-dashes, or regex metacharacters false-negative under pattern matching, and line-wrapped sources miss on the joined form — a grep miss on a punctuated or wrapped quote means Read the file before declaring the finding phantom. If a just-written file's on-disk content genuinely differs from what the session wrote, don't stop at "agent misread" — check for a mutating tool in the write path (e.g., a YAML round-trip normalizer) and root-cause the pattern.
- **Verify rule *interpretation*, not just content quotes**: a [CONFLICT] finding can quote real text yet over-stretch the rule's meaning — check the rule's provenance/trigger context before presenting, and present over-readings as "verified phantom" with reasoning rather than silently dropping them.
- **Convert timezones before accepting timestamp-inconsistency findings**: file-metadata timestamps are typically UTC while narrative dates in memory bodies follow the author's local timezone — a post-midnight local session stamps the next UTC day, so "modified predates its own content" claims must be re-derived in one timezone before presenting.
